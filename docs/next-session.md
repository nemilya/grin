# Следующая сессия

## 1. Горизонтальная компоновка (16:9)

**Сделано:** `story.json → formats.horizontal`, `storyboard-16x9.json` (extends + cams + shots/drop/add), субтитры по
формату, `make … F=horizontal`, экспорт `.srt` и глав для YouTube (`make youtube F=horizontal`), версия для соцсетей
1280×720. Камеры 16:9 проверены по стоп-кадрам всех 133 кадров (заглушки) и демо-финала (готовые ассеты);
узкие куски декораций (стена с окном, заборы, трава, стена спальни) расширены в библии — сгенерируются уже широкими.

**Осталось:** пройтись по кадрам после первого полного рендера (всё сгенерировано и просмотрено по стоп-кадрам обоих форматов), решить по диалогам
«восьмёрка или двойной план» (сейчас — восьмёрка с планами через плечо, в 16:9 это работает). Не вшивать субтитры
(для `.srt` на YouTube) — уже можно: `"subtitles": {"burn": false}` в формате.

Ниже — исходный план (для справки).

### Модель данных

- `story.json → films`: несколько форматов вместо одного `film`:
  ```json
  "films": {
    "vertical":   {"width": 1080, "height": 1920, "storyboard": "storyboard.json"},
    "horizontal": {"width": 1920, "height": 1080, "storyboard": "storyboard-16x9.json"}
  }
  ```
  `make timeline F=horizontal` → `build/timeline-horizontal.json`, рендер — `--tl horizontal`.
- `storyboard-16x9.json` наследует вертикальную (`"extends": "storyboard.json"`) и переопределяет только
  `cams` и отдельные кадры (`"shots": {"s05g": {...}}`). Реплики, свет, звук, состояние сцены — общие.
  Таймлайн применяет переопределения поверх развёрнутой вертикальной раскадровки.
- Кадры можно **сливать**: где в вертикали восьмёрка «доктор / пациент», в горизонтали — один двойной план
  (`"merge": ["s03a", "s03b"]`), и наоборот.

### Что меняется в постановке

| | 9:16 | 16:9 |
|---|---|---|
| Диалог | восьмёрка одиночных планов | двойной план через стол, наезды вместо склеек |
| Процессия | по одной фигуре в узком окне | всё окно и улица, фигуры идут цепочкой — видна «смена возрастов» целиком |
| Стены падают | вертикальный отъезд | ширина коробки, боковые стены раскрываются как створки |
| Поднятая рука | рука во весь рост кадра | низкий ракурс, рука уходит за верх кадра |
| Субтитры | 73% высоты, 2 строки по ~32 знака | нижняя треть, 1–2 строки по ~45 знаков (`SUB_MAX_CHARS` из формата) |
| Задники | 64×48 см хватает | шире (80–90 см) — дорисовать края (outpaint) или новые задники 16:9 |

### Работа

1. `timeline.py`: форматы, `extends`, переопределения кадров, субтитры по ширине кадра.
2. `stage/`: размер из таймлайна уже берётся; безопасная зона — по формату; `wrap()` — по ширине.
3. Камеры 16:9 для всех декораций (`cams`), просмотр листом `make stills F=horizontal`.
4. Задники шире: `assets.py` — `aspect` из формата, перегенерация задников и полов (~10 картинок, ≈ $0.2).
5. Проверка: оба формата из одного состояния — тест «тот же набор элементов в кадре s05g в обоих форматах».

## 2. Можно ли без ИИ-агента — одним скриптовым пайплайном?

**Да.** Всё, что в этой сессии делал агент (Claude Code), — это либо вызовы API, либо творческие решения,
которые можно выразить промптом с проверкой. Агент нужен был, чтобы быстро придумать и отладить; для
следующих рассказов тот же путь превращается в скрипты `make`:

| этап | сейчас | без агента |
|---|---|---|
| Подготовка текста | `make prepare` | ✓ уже скрипт |
| Глоссарий, перевод | агент перевёл вручную | ✓ `make translate` — уже есть (OpenRouter, Opus; как в mountain-rock) |
| Библия: мир, герои, позы, декорации | агент написал | `engine/bible.py analyze`: LLM по тексту → JSON по схеме (образец — `illustrate.analyze_section` в mountain-rock), позы — из сцен раскадровки |
| Раскадровка | агент написал | `engine/board.py draft`: LLM получает текст с id предложений, библию, словарь камер/эффектов и *эту* раскадровку как образец → JSON; **валидатор** (`timeline.build` → ошибки, длины кадров, камеры, существующие ассеты) возвращает ошибки в LLM до чистого результата |
| Ассеты | ✓ `make assets-used` | ✓ |
| Озвучка | ✓ `make voice` | ✓ |
| Звук | ✓ `make sound` | музыкальные кюи — тоже LLM-черновиком (по сценам) или своя музыка файлом |
| Рендер | ✓ `make video` | ✓ |
| Контроль качества | агент смотрел листы кадров и правил камеры/свет | `engine/review.py`: лист стоп-кадров → vision-модель → JSON-правки (камера ближе/дальше, свет, перекрытия) → пересборка; плюс автоматические проверки: средняя яркость кадра, доля пустого кадра, пересечение главного героя с краем |

Что остаётся человеку: выбрать рассказ и голос, утвердить библию и раскадровку (это тот же JSON — правится
руками или в простой админке, как в mountain-rock), посмотреть лист кадров, решить «нравится / переделать».
Цена полного прогона рассказа такого размера: перевод ≈ $0.2, библия + раскадровка ≈ $0.3–0.5,
ассеты ≈ $1.5 (≈ 75 картинок), озвучка ≈ $0.2 — **около $2–3**.

### План работ

1. `engine/bible.py` — анализ текста → библия (позы — по сценам), с проверкой схемы.
2. `engine/board.py` — черновик раскадровки сценами (по 1–3 абзаца на запрос, с контекстом предыдущих
   сцен) + цикл «валидатор → исправь».
3. `engine/review.py` — проверки кадров (без модели) + необязательный проход vision-моделью.
4. `make film S=<рассказ>` — всё подряд: prepare → translate → bible → board → assets → voice → timeline →
   sound → stills (стоп для утверждения) → video.
5. Простая админка (как в mountain-rock) — библия, раскадровка с превью кадра, утверждение.
