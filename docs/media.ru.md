# Как связаны `grin` и `grin-media`

[English](media.md) · **Русский**

Если коротко: **`grin` — главный репозиторий, [`grin-media`](https://github.com/nemilya/grin-media) — склад файлов
к нему.** Связывает их одна строка в `grin`: файл `media.rev`.

## Одна папка, два git-репозитория

```
grin/                          ← папка на диске
├── .git/                      ← git репозитория grin: видит код и JSON, а картинки и звук игнорирует (.gitignore)
├── .media.git/                ← git репозитория grin-media: видит только медиа в stories/
├── media.rev                  ← в grin: «к этому коммиту нужна версия медиа 5bf11a8»
├── engine/  stage/  site/ …   ← только grin
└── stories/mate-in-3/assets/
    ├── assets.json            ← grin: список ассетов, промпты, отпечатки
    └── doctor/seated.webp     ← grin-media: сама картинка
```

Оба репозитория пишут в одну и ту же папку, поэтому движок ничего про это не знает: картинка лежит там же, где
лежала раньше. Каждый файл принадлежит ровно одному из репозиториев.

| | `grin` | `grin-media` |
|---|---|---|
| что | код, тексты, переводы, библии, раскадровки, манифесты (`assets.json`, `voicing.json`) | `stories/**/*.webp` (вырезки, декорации), `*.jpg` (листы героев), `*.opus` (дубли озвучки) |
| git-папка | `.git/` | `.media.git/` (создаёт `make media-pull`) |
| объём | ≈ 1,5 МБ | ≈ 0,3 ГБ, растёт с каждой новой или перерисованной картинкой |
| кто коммитит | вы / Claude Code, как обычно | только `make media-push` |

Ни там, ни там: `assets/takes/` (прежние варианты картинок), `assets/raw/` (исходники до ключа), `build/`, `out/`,
`dist/` — только локально.

## Как они связаны: `media.rev`

`grin-media` — это просто последовательность снимков медиа:

```
grin-media:  be76cbf (README) → cfccf96 → 0fda1c5 → 3837137 → 2bae254 → 5bf11a8 (leaf-story)
                                                                          ↑
grin:        59fcd6f, 33e70d7 ─── media.rev = 5bf11a8 ──────────────────┘
```

Сам по себе `grin-media` не знает, к какому коду относится. Это говорит `grin`: «моему коммиту нужен снимок медиа
5bf11a8». Это как git submodule, только файлы раскладываются по тем же папкам, а не в отдельную подпапку.

## Пример: перерисовали одну картинку

| шаг | что происходит в `grin` | что происходит в `grin-media` |
|---|---|---|
| `make assets … --redo doctor/seated` | в `assets.json` меняются seed и отпечаток (пока не закоммичено) | на диске новый `seated.webp` (пока не закоммичен) |
| `make media-push` | `media.rev` меняется с `5bf11a8` на `M2` и добавляется в коммит | новый коммит `M2` (родитель `5bf11a8`) с одним файлом, пуш в `main` |
| `git commit` + `git push` | коммит `C2` содержит `assets.json` и `media.rev = M2`; хук проверяет, что `M2` уже в `grin-media` | — |
| на другой машине: `git pull` | приходит `C2`, в нём `media.rev = M2` | на диске ещё старая картинка; `make status` пишет «media.rev wants M2», генерация и `make site` не запустятся |
| там же: `make media-pull` | — | скачивается `M2`, `seated.webp` заменяется |

Старая версия при этом никуда не пропадает. Если откатить `grin` на старый коммит (`git checkout C1`), там
`media.rev = 5bf11a8`, и `make media-pull` вернёт старую картинку.

## Правило для ежедневной работы

- **После `git pull` всегда делайте `make media-pull`.** Код говорит, какая версия медиа нужна, а эта команда её приносит.
- **Перед `git push` нужен `make media-push`,** если что-то генерировали. Сначала заливаются картинки, потом код,
  который на них ссылается. В облачной сессии Claude Code пушить пораньше: всё незапушенное пропадёт вместе с контейнером.

Если забыть, есть защиты:
- забыли `media-push` — хук `pre-push` не пропустит `git push`;
- забыли `media-pull` — `make status` покажет расхождение, а генерация и сборка сайта не запустятся (иначе свежий клон
  + `make assets` перегенерировал бы весь фильм за деньги; обойти — `MEDIA_CHECK=0`).

## Ветки

Ветка в `grin-media` называется так же, как в `grin`: `main` → `main`, `claude/x` → `claude/x`. Так эксперименты
в ветке не попадают в медиа основной ветки. Если двое залили медиа одновременно, `media-push` сам сольёт изменения,
не трогая файлы вне `stories/`; конфликт — только если с обеих сторон изменён один и тот же файл.

## Команды

```bash
make media-pull            # медиа из media.rev (LATEST=1 — последние в ветке медиа; FORCE=1 — отбросить локальные правки)
make media-push            # закоммитить и запушить изменённые медиа, записать media.rev и добавить его в коммит (MSG="…" — сообщение)
make media-status          # скачаны ли, что изменено локально, что не запушено
```

Код — `engine/media.py`, тесты — `tests/test_media.py`, хук — `tools/hooks/pre-push`.

**Откуда берутся медиа.** Адрес `grin-media` повторяет адрес `grin`: склонировали `grin` по ssh
(`git@github.com:nemilya/grin.git`) — медиа тоже по ssh (`git@github.com:nemilya/grin-media.git`), теми же ключами;
по https — по https. Пока репозитории приватные, https спрашивает логин GitHub (и токен, а не пароль) — лучше
клонировать по ssh. `MEDIA_REMOTE` в `local.mk` задаёт адрес явно (например, зеркало на своём сервере).

## Чего делать не нужно

- **Клонировать `grin-media` отдельно.** Он живёт внутри папки `grin` как `.media.git`, его создаёт `make media-pull`.
- **Коммитить в `grin-media` руками.** Это делает только `make media-push`.
- **Коммитить медиа в `grin`.** Не пропустят `.gitignore` и проверка в CI.

## Почему так

Раньше всё было в одном репозитории: за несколько рассказов `.git` вырос до 963 МБ — каждая перерисованная картинка
остаётся в истории навсегда, а историю открытого репозитория не переписать. Теперь `grin` остаётся ≈ 1,5 МБ; `grin-media`,
когда дорастёт до нескольких ГБ, можно сжать до текущего снимка (старую историю — в архив на свои серверы) или перенести
в другое хранилище — команды `make media-*` останутся теми же. Вырезки хранятся в WebP без потерь (те же пиксели,
что PNG, ≈ 45 % объёма).
